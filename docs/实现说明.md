# 实现说明（V0.1）

这份文档说明"需求/架构文档 → 代码"的落地情况，以及这一版有意做出的取舍，方便后续接手的人知道哪里是坑。

## 1. 模块与依赖方向

```
:app  →  :core:model, :core:calculation
:core:calculation → :core:model
```

- `core:model`、`core:calculation` 是纯 Kotlin/JVM 模块，没有 Android 依赖，所以计算规则可以用普通 JVM 单测覆盖（`./gradlew :core:calculation:test`）。
- 其余部分（仓库实现、Room、DataStore、Compose）按架构文档 ADR-004 先合并进 `:app`，按包分层；以后要拆 `core:data`、`feature:*` 时，直接按包平移即可。
- 依赖注入用 `di/AppContainer` 手动组装。接口都定义在 `domain/repository`，换实现不影响用例和界面。

## 2. 计算规则（唯一事实源）

`core/calculation/CalculationEngine` 是唯一算法实现，录入页预览与保存落库都调用它。

- 结束时间不晚于开始时间 → 自动加一天，并给"已按次日计算"提示
- 时长 = 结束 − 开始 − 休息扣除
- 小时工资：时薪模式直接取；月薪模式 = 月薪 ÷ 计薪天数 ÷ 日标准工时
- 金额 = 小时工资 × 分钟 ÷ 60 × 倍率，全程 BigDecimal，最后一步 HALF_UP 到分
- 倍率用"千分基点"：1500 = 1.5 倍（与架构文档字段命名一致）
- 手动金额优先于自动金额，但自动值仍会算出来写进规则快照

边界：单条时长 1–1440 分钟；休息 0–1439 分钟且必须小于总时长；备注 ≤ 200 字；手动金额 ≤ 100 万元。校验统一在用例层，界面只做即时提示。

## 3. 数据与快照

- 金额存 `Long` 分，倍率存 `Int` 千分基点，时间存 epoch，展示时按系统时区还原
- 每条记录保存 `rule_snapshot_json`（规则原始值 + 这次算出的时薪/倍率），改规则不会污染历史
- 月度/年度统计全部走 SQL 聚合（`SUM`、`GROUP BY`、`COUNT(DISTINCT)`），不加载全量实体
- 调休获得量来自加班记录的 `comp_time_minutes` 汇总，使用量来自 `comp_time_usages`

详见 [数据库设计](数据库设计.md)。

## 4. 与架构文档的偏差（有意为之）

| 架构文档 | 当前实现 | 原因 |
| --- | --- | --- |
| Hilt | `AppContainer` 手动注入 | 先确保 AGP 9 + Kotlin 2.4 的编译链稳定；依赖都走接口，后续换 Hilt 只改容器 |
| Paging 3 | 按月份区间查询 + `LazyColumn` | 单月数据量有限，Paging 的收益要等"全部月份"大数据量场景；接口 `observeRecords` 已按可分页的形态设计 |
| JUnit 5 | JUnit 4 | 架构文档允许 JUnit4/JUnit5；JUnit4 与 Android 单测环境零配置 |
| Vico / MPAndroidChart | Compose 自绘条形图 | 先避免额外依赖与体积，`ChartSeries` 形态的接口后续再抽 |
| Navigation 类型安全路由 | 字符串路由 + 可选参数 | 类型安全路由需要 kotlinx.serialization 插件；当前只有 9 个路由，字符串足够 |
| CSV 导出 | 已实现（SAF + RFC 4180 + BOM） | 逻辑层已单测；系统文件选择器那一步需要真机/可用模拟器手动确认 |

## 5. 已知限制

- 模拟器（无窗口模式）上系统文件选择器的"保存"按钮点击不稳定，导出流程需要在真机上再确认一次
- 年度统计的月份聚合用 SQLite `strftime` 从"天序号"换算，年份范围外（<1970）的数据不适用
- 清除数据只清记录和调休，不重置薪资规则与偏好设置（避免误删配置）
- 还没有数据库迁移：当前 `version = 1`，第一次改表前要先把 `exportSchema` 打开并提交 schema
