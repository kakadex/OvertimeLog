# 数据库设计（Room，version 1）

数据库文件：`overtimelog.db`（应用私有目录，不加密，V1 范围见架构文档 ADR-008）。

## 1. 约定

| 类型 | 存法 | 原因 |
| --- | --- | --- |
| 金额 | `INTEGER`，单位"分" | 避免浮点误差，SQL 可直接 `SUM` |
| 倍率 | `INTEGER`，千分基点（1500 = 1.5 倍） | 同上 |
| 日期 | `INTEGER`，`LocalDate.toEpochDay()` | 范围查询、按月分组都靠它 |
| 时间点 | `INTEGER`，epoch 毫秒 | 展示时按系统时区还原 |
| 枚举 | `TEXT`，存枚举的 `code` | 可读、可加值，不依赖序号 |
| 小数 | `TEXT`（如 `21.75`、`8`） | 保留 BigDecimal 精度，避免二进制浮点 |

## 2. 表结构

### overtime_records（加班记录）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK 自增 | |
| work_id | INTEGER NULL | 预留多工作/项目维度 |
| date_epoch_day | INTEGER | 归属日期 |
| start_epoch_millis / end_epoch_millis | INTEGER | 起止时间（跨天时 end 已是次日） |
| break_minutes | INTEGER | 休息扣除 |
| type | TEXT | WORKDAY / REST_DAY / HOLIDAY / CUSTOM |
| duration_minutes | INTEGER | 计算后的时长 |
| hourly_rate_cents | INTEGER | 保存时的时薪（分） |
| multiplier_bp | INTEGER | 保存时的倍率 |
| amount_cents | INTEGER | 最终金额（分），手动改过就用手动值 |
| comp_time_minutes | INTEGER | 折算的调休分钟 |
| comp_time_mode | TEXT | NONE / RATIO_1_1 / RATIO_1_1_5 / MANUAL |
| manual_amount_cents | INTEGER NULL | 手动金额；为空表示自动计算 |
| settlement_status | TEXT | UNSETTLED / SETTLED |
| note | TEXT | ≤ 200 字 |
| rule_snapshot_json | TEXT | 规则快照（含算出值） |
| created_at / updated_at | INTEGER | epoch 毫秒 |

索引：`date_epoch_day`、`type`、`settlement_status`、`(date_epoch_day, type)`。

### salary_rules（薪资规则）

保存新规则时插入一行并把旧行置为 `active = 0`，所以历史规则可追溯。

| 列 | 说明 |
| --- | --- |
| calculation_mode | HOURLY / MONTHLY |
| monthly_salary_cents / hourly_rate_cents | 两种模式各自的输入 |
| pay_days / standard_hours_per_day | 字符串存 BigDecimal，默认 `21.75` / `8` |
| workday / rest_day / holiday / custom_multiplier_bp | 各类型倍率 |
| comp_time_ratio_bp | 默认调休比例（1000 / 1500） |
| effective_from | 生效时间 |
| active | 1 = 当前规则 |

### comp_time_usages（调休使用）

| 列 | 说明 |
| --- | --- |
| date_epoch_day | 使用日期 |
| minutes | 使用分钟数 |
| note | 备注 |
| created_at | 创建时间 |

余额 = `SUM(overtime_records.comp_time_minutes) − SUM(comp_time_usages.minutes)`，在 SQL 层聚合。

### holiday_overrides（节假日人工覆盖，预留）

V1 不内置法定节假日数据（年份/地区差异大），表先建好，V1.1 接 `HolidayProvider` 时直接用。

| 列 | 说明 |
| --- | --- |
| date_epoch_day | 主键 |
| is_holiday | 是否节假日 |
| name | 名称 |

## 3. 关键查询

- 列表：`WHERE date_epoch_day BETWEEN ? AND ? AND (type = ? OR ? IS NULL) ... ORDER BY start_epoch_millis DESC`
- 月度合计：`SUM(duration_minutes)`、`SUM(amount_cents)`、按 `settlement_status` 条件求和、`COUNT(DISTINCT date_epoch_day)`
- 按类型：`GROUP BY type`
- 日历：`GROUP BY date_epoch_day` + `GROUP_CONCAT(DISTINCT type)`
- 年度：`strftime('%m', date_epoch_day * 86400, 'unixepoch')` 后 `GROUP BY month`

## 4. 迁移计划

当前只有 `version = 1`，没有线上数据。第一次改表时：

1. 打开 `exportSchema = true`，把 schema JSON 提交进仓库
2. 写 `Migration(1, 2)`，在 `Room.databaseBuilder(...).addMigrations(...)`
3. 加 instrumentation 迁移测试（建 v1 库 → 跑迁移 → 校验数据与列）
